# PASO 00.01 — Preparación y comprobaciones antes de tocar una VM

## Archivos relacionados y por qué importan

- **[`docs/operacion/INVENTARIO-POR-INTEGRANTE.md`](../../operacion/INVENTARIO-POR-INTEGRANTE.md)**: identificación de CPU/RAM/disco/red real por VM antes de aplicar recetas.

**Lugar de ejecución:** terminal de Ubuntu Server (no la terminal del host Windows ni del contenedor, salvo cuando el comando sea `docker compose exec`). Confirmar direcciones reales y el estado actual de la VM antes de copiar comandos.

## Propósito del paso y contexto operacional

Preparación del entorno y condiciones de reproducción en una VM nueva.

Este archivo corresponde **exclusivamente al paso 00-01**, con comandos históricos literales y mejoras razonadas. En una **VM ya configurada** se inspeccionan primero los servicios y datos; no se vuelven a crear credenciales ni volúmenes. Los resultados observados en las capturas pertenecen a la sesión que los originó, no al conjunto de cinco integrantes.

## Comprobación recomendada y salida a documentar

Guardar una tabla por máquina con SO, RAM, CPU, almacenamiento, hipervisor, interfaces y disponibilidad de paquetes; registrar divergencias.

Registrar el resultado exacto, fecha, sistema y si la prueba pasó o falló. Para un cambio de configuración conservar el archivo anterior y ejecutar la validación sintáctica antes de reiniciar el servicio. La **ruta versionable recomendada** está explicada en [`infra/`](../../../infra/README.md), sin sustituir los comandos originales que aparecen abajo.

> Procedimiento complementario para reconstruir fases anteriores no explicadas íntegramente en el texto pegado. No sustituye verificación en cada VM.

Ejecutar en Ubuntu (no cambia configuración):

```bash
hostnamectl
cat /etc/os-release
uname -a
whoami
ip -br address
ip route
lsblk -f
df -hT
free -h
sudo ss -lntup
```

**En VirtualBox:** confirmar adaptador NAT del servidor y red interna común entre las dos VMs. Registrar el nombre de la red interna, no añadir un NAT innecesario a Mint.

**Control de datos:** si Moodle ya está instalado no ejecutar scripts de instalación nuevamente; documentar salida de `docker compose ls` y `docker volume ls` primero.
