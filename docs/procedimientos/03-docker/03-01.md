## Propósito del paso y contexto operacional

Docker Engine y Compose: instalación, versión y comprobación de capacidad del host.

Este archivo corresponde **exclusivamente al paso 03-01**, con comandos históricos literales y mejoras razonadas. En una **VM ya configurada** se inspeccionan primero los servicios y datos; no se vuelven a crear credenciales ni volúmenes. Los resultados observados en las capturas pertenecen a la sesión que los originó, no al conjunto de cinco integrantes.

## Comprobación recomendada y salida a documentar

Ejecutar `docker --version`, `docker compose version`, `sudo docker info`, `sudo docker system df`; comprobar servicio sin instalar otro Docker.

Registrar el resultado exacto, fecha, sistema y si la prueba pasó o falló. Para un cambio de configuración conservar el archivo anterior y ejecutar la validación sintáctica antes de reiniciar el servicio. La **ruta versionable recomendada** está explicada en [`infra/`](../../../infra/README.md), sin sustituir los comandos originales que aparecen abajo.

> Procedimiento complementario para reconstruir fases anteriores no explicadas íntegramente en el texto pegado. No sustituye verificación en cada VM.

La bitácora aporta evidencia de Docker en funcionamiento, no prueba la instalación idéntica en cada VM. No reinstalar si funciona.

```bash
docker --version
docker compose version
sudo docker info
sudo docker compose ls
sudo docker image ls
sudo docker volume ls
```

Para una VM nueva, seguir la [instalación oficial para Ubuntu](https://docs.docker.com/engine/install/ubuntu/) compatible con la versión del sistema. Registrar versión exacta de Engine/Compose y no usar `curl | sh` ciegamente.
