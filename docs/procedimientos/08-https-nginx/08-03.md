## Procedimiento completo y comandos originales

En Ubuntu:

```
sudo nano /etc/nginx/sites-available/moodle
```

Pegá:

```
server {
    listen 192.168.50.1:80;

    server_name aulavirtual.ctcr;

    return 301 https://$host$request_uri;
}

server {
    listen 192.168.50.1:443 ssl;

    server_name aulavirtual.ctcr;

    ssl_certificate /etc/nginx/certs/ctcr.crt;
    ssl_certificate_key /etc/nginx/certs/ctcr.key;

    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://192.168.50.1:8080;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;

        proxy_http_version 1.1;

        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

Guardá el archivo.

#### EV-117 · VirtualHost aulavirtual.ctcr

![VirtualHost aulavirtual.ctcr](08-03/evidencias/EV-117.webp)

**Qué se observa:** `/etc/nginx/sites-available/aulavirtual.ctcr` con dos bloques: `listen 192.168.50.1:80` que responde `return 301 https://$host$request_uri;`, y `listen 192.168.50.1:443 ssl` con el certificado y la clave, `ssl_protocols TLSv1.2 TLSv1.3`, `client_max_body_size 100M`, `proxy_pass http://127.0.0.1:8080`, cabeceras `Host`, `X-Real-IP`, `X-Forwarded-For` y `X-Forwarded-Proto https`, y tiempos de espera de 300 s.

**Qué significa y qué no prueba:** Es la configuración real del proxy en esta VM. `X-Forwarded-Proto https` y `MOODLE_SSL_PROXY` (08-05) hacen que Moodle genere enlaces HTTPS. **Ficha:** [EV-117](08-03/evidencias/EV-117.md).
