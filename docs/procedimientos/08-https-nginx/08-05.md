## Procedimiento completo y comandos originales

Ahora necesitamos indicarle al contenedor que su dirección definitiva será HTTPS. **Este paso recrea Moodle**: no lo ejecutes sin antes cumplir todo esto.

Antes de empezar (obligatorio):

1. Snapshot de la VM en VirtualBox.
2. Respaldo SQL manual (procedimiento [10-02](../10-respaldos/10-02.md)) y copia del volumen `moodle_data`.
3. Confirmá que sabés volver atrás (sección Rollback al final).

Esta variante aplica a la VM con el Compose histórico (`~/proyecto-moodle/compose.yaml`, URL y puerto literales). Si usás el Compose del repositorio con `.env`, editá `MOODLE_URL`, `MOODLE_BIND_IP` y `MOODLE_SSL_PROXY` en el `.env` según [`.env.https.example`](../../../infra/compose/.env.https.example).

En Ubuntu:

```
cd ~/proyecto-moodle
```

Guardá una copia del Compose anterior:

```
cp compose.yaml compose-http.backup.yaml
```

Abrí:

```
nano compose.yaml
```

Buscá esta línea:

```
MOODLE_URL: http://192.168.50.1:8080
```

Reemplazala por:

```
MOODLE_URL: https://moodle.ctcr.test
```

En la sección `environment` del servicio `moodle`, agregá:

```
MOODLE_SSL_PROXY: "yes"
```

Esta opción le indica a Moodle que HTTPS termina en un proxy situado delante del contenedor.

Para que el puerto 8080 no quede expuesto a toda la red interna, también es recomendable cambiar:

```
- "192.168.50.1:8080:8080"
```

Por:

```
- "127.0.0.1:8080:8080"
```

Y en el archivo de Nginx reemplazar:

```
proxy_pass http://192.168.50.1:8080;
```

Por:

```
proxy_pass http://127.0.0.1:8080;
```

Así, Moodle solo se comunica directamente con Nginx desde el propio Ubuntu Server, y los clientes utilizan HTTPS.

Validá y aplicá:

```
sudo docker compose config --quiet
```

```
sudo docker compose up -d
```

Después:

```
sudo nginx -t && sudo systemctl reload nginx
```

Verificá que Moodle tomó la URL nueva (no asumas que la variable basta: `config.php` vive en el volumen y puede conservar la URL de la primera instalación):

```
sudo docker compose exec moodle grep -nE 'wwwroot|sslproxy' /var/www/moodle/config.php
```

Debe mostrar `https://moodle.ctcr.test` y `sslproxy = true`. Si sigue mostrando `http://192.168.50.1:8080`, editá esas dos líneas de `config.php`, ejecutá `php admin/cli/purge_caches.php` dentro del contenedor y guardá la salida como evidencia.

Rollback (si Moodle no abre o redirige mal):

```
cd ~/proyecto-moodle
cp compose-http.backup.yaml compose.yaml
sudo docker compose up -d
sudo rm /etc/nginx/sites-enabled/ctcr-moodle && sudo nginx -t && sudo systemctl reload nginx
```

Los volúmenes no se tocan; Moodle vuelve a `http://192.168.50.1:8080`.

## Correcciones y precauciones aplicables

Cambiar `MOODLE_URL` + `MOODLE_SSL_PROXY` (Oksigenia) y el listener 8080 a 127.0.0.1 implica recrear Moodle. Requiere respaldo y verificación de `wwwroot`, TLS, redirecciones y contenido. Usar el mismo proyecto Compose.
