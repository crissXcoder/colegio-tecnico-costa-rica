# EV-119 — Compose cambiado a 127.0.0.1:8080 y URL HTTPS

**Procedencia:** Documento del grupo «Proyecto Colegio Técnico con departamentos separados» (PDF de 54 páginas), página 39–41. Captura real del grupo en la VM `server@server` (usuario `server`, Ubuntu Server con `enp0s8` 192.168.50.1), distinta de la VM de Criss (`criss@server`). **Paso relacionado:** [08-05](../../08-05.md).

![EV-119 — Compose cambiado a 127.0.0.1:8080 y URL HTTPS](EV-119.webp)

## Qué ocurre en esta captura

Se respalda el compose (`cp compose.yaml compose-http.backup.yaml`) y se edita el servicio `moodle`: `ports: "127.0.0.1:8080:8080"`, `MOODLE_URL: https://aulavirtual.ctcr` y `MOODLE_SSL_PROXY: "yes"`. Luego `docker compose config --quiet`, `up -d` (db Healthy, moodle Started) y `ps` con ambos `healthy` y moodle en `127.0.0.1:8080->8080/tcp`. La prueba por PHP CLI devuelve `https://aulavirtual.ctcr`.

## Interpretación y límite de la evidencia

Moodle deja de estar expuesto en la red interna y solo se llega por Nginx. Los volúmenes no se tocaron: el contenedor se recreó con los mismos datos. La captura también muestra la variable mal escrita `MOODLE_BD_TYPE` (con `BD`), que la imagen ignora; no corregirla después de armar el paquete (P-15).

## Reproducir y verificar

1. Seguir el procedimiento [08-05](../../08-05.md) en la VM que se vaya a presentar.
2. Comparar la salida con esta captura; las rutas, nombres de usuario y versiones pueden variar entre VMs del grupo (ver ADR-0004).
3. Si la salida cambia, crear una evidencia nueva en lugar de reemplazar esta.
