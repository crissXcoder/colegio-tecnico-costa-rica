## Propósito del paso y contexto operacional

FTPS con vsftpd: cuentas sin shell, chroot, directorios propios y denegación documentada de acceso cruzado.

Este archivo corresponde **exclusivamente al paso 09-02**, con comandos históricos literales y mejoras razonadas. En una **VM ya configurada** se inspeccionan primero los servicios y datos; no se vuelven a crear credenciales ni volúmenes. Los resultados observados en las capturas pertenecen a la sesión que los originó, no al conjunto de cinco integrantes.

## Comprobación recomendada y salida a documentar

`sudo systemctl is-active vsftpd`, prueba FTPS de subida/listado y acceso de usuario A a ruta de B, comprobando rechazo y registrando código de error.

Registrar el resultado exacto, fecha, sistema y si la prueba pasó o falló. Para un cambio de configuración conservar el archivo anterior y ejecutar la validación sintáctica antes de reiniciar el servicio. La **ruta versionable recomendada** está explicada en [`infra/`](../../../infra/README.md), sin sustituir los comandos originales que aparecen abajo.

## Antes de ejecutar

- [ ] Identificar VM, interfaz e IP actual; no asumir la IP de otra persona.
- [ ] Inspeccionar el estado actual del servicio. Si hay datos o volúmenes existentes, respaldarlos antes de cambios.
- [ ] Registrar fecha, integrante responsable, revisor y versión vigente en la sesión de bitácora.

## Procedimiento completo y comandos originales

Utilizaremos **seis cuentas, una por funcionario**, agrupadas por departamento (cumple "por integrante o por rol"). Los nombres vienen de [DATOS-MAESTROS](../../00-proyecto/DATOS-MAESTROS.md) (sección 9); son cuentas Linux independientes de las de Moodle.

| Cuenta            | Departamento   |
| ----------------- | -------------- |
| `marta.jimenez`   | Administración |
| `carlos.mendez`   | Administración |
| `sofia.hernandez` | Docencia       |
| `jose.ramirez`    | Docencia       |
| `valeria.sanchez` | Informática    |
| `diego.fernandez` | Informática    |

```
sudo adduser marta.jimenez
sudo adduser carlos.mendez
sudo adduser sofia.hernandez
sudo adduser jose.ramirez
sudo adduser valeria.sanchez
sudo adduser diego.fernandez
```

Cada comando solicita la contraseña: usá la acordada por el grupo para esa cuenta (convención en DATOS-MAESTROS, sección 1; nunca en Git).

No hace falta colocar información personal en los campos adicionales del asistente.

Para impedir que estas cuentas puedan utilizar una consola interactiva del servidor:

```
for u in marta.jimenez carlos.mendez sofia.hernandez jose.ramirez valeria.sanchez diego.fernandez; do
    sudo usermod -s /usr/sbin/nologin "$u"
done
```

Comprobá:

```
getent passwd marta.jimenez
```

#### EV-124 · Cuentas FTP con guion bajo y shell nologin

![Cuentas FTP con guion bajo y shell nologin](09-02/evidencias/EV-124.webp)

**Qué se observa:** `adduser` crea `marta_jimenez`, `carlos_mendez` (Administración), `sofia_hernandez`, `jose_ramirez` (Docencia), `valeria_sanchez` y `diego_fernandez` (Informática), pidiendo la contraseña sin mostrarla. Luego un ciclo `usermod -s /usr/sbin/nologin` para las seis.

**Qué significa y qué no prueba:** En esta VM los usuarios se crearon con **guion bajo** para evitar que `adduser` rechace el punto (INC-007). DATOS-MAESTROS y la VM de Criss usan `marta.jimenez`: los nombres FTP **no coinciden entre VMs** (P-17). `nologin` impide entrar por consola o SSH. **Ficha:** [EV-124](09-02/evidencias/EV-124.md).
