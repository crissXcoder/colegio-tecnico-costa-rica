## Procedimiento completo y comandos originales

Primero respaldá el archivo original:

```
sudo cp /etc/vsftpd.conf /etc/vsftpd.conf.bak
```

Abrí:

```
sudo nano /etc/vsftpd.conf
```

Para este laboratorio, reemplazá el contenido por:

```
listen=YES
listen_ipv6=NO
listen_address=192.168.50.1

anonymous_enable=NO
local_enable=YES
write_enable=YES

local_umask=077

chroot_local_user=YES
allow_writeable_chroot=NO

userlist_enable=YES
userlist_deny=NO
userlist_file=/etc/vsftpd.user_list

local_root=/srv/ftp/$USER

pasv_enable=YES
pasv_min_port=40000
pasv_max_port=40010
pasv_address=192.168.50.1

ssl_enable=YES
rsa_cert_file=/etc/nginx/certs/colegio.crt
rsa_private_key_file=/etc/nginx/certs/colegio.key

force_local_logins_ssl=YES
force_local_data_ssl=YES

ssl_tlsv1=YES
ssl_sslv2=NO
ssl_sslv3=NO

require_ssl_reuse=NO

xferlog_enable=YES
```

Utilizamos FTPS explícito para proteger las credenciales y las transferencias mediante TLS. El certificado es el mismo que creamos para el laboratorio HTTPS.

No estamos configurando SFTP: ese es otro protocolo diferente que funciona sobre SSH.

## Correcciones y precauciones aplicables

**Corrección necesaria:** añadir `user_sub_token=$USER` para que `local_root=/srv/ftp/$USER` se resuelva como se espera. El ejemplo de `infra/vsftpd/` tiene la corrección. Verificar compatibilidad PAM, TLS y directorios antes del reinicio.
