## Propósito del paso y contexto operacional

FTPS con vsftpd: cuentas sin shell, chroot, directorios propios y denegación documentada de acceso cruzado.

Este archivo corresponde **exclusivamente al paso 09-07**, con comandos históricos literales y mejoras razonadas. En una **VM ya configurada** se inspeccionan primero los servicios y datos; no se vuelven a crear credenciales ni volúmenes. Los resultados observados en las capturas pertenecen a la sesión que los originó, no al conjunto de cinco integrantes.

## Comprobación recomendada y salida a documentar

`sudo systemctl is-active vsftpd`, prueba FTPS de subida/listado y acceso de usuario A a ruta de B, comprobando rechazo y registrando código de error.

Registrar el resultado exacto, fecha, sistema y si la prueba pasó o falló. Para un cambio de configuración conservar el archivo anterior y ejecutar la validación sintáctica antes de reiniciar el servicio. La **ruta versionable recomendada** está explicada en [`infra/`](../../../infra/README.md), sin sustituir los comandos originales que aparecen abajo.

## Procedimiento completo y comandos originales

### 9.8. Crear documentos de prueba

En Ubuntu Server, creamos tres documentos representativos de los tres departamentos institucionales:

```bash
echo "CTCR - Expediente administrativo de prueba" > /tmp/expediente-administrativo.txt
echo "CTCR - Planificacion docente de prueba" > /tmp/planificacion-docente.txt
echo "CTCR - Informe de soporte informatico de prueba" > /tmp/informe-soporte.txt
```

Son archivos de demostración del servicio FTP institucional y no sustituyen los recursos PDF académicos cargados previamente en Moodle.

### 9.9. Probar subida de archivos

Utilizamos `curl` con soporte FTPS explícito (`--ssl-reqd`) y certificado del laboratorio (`--insecure`).

**1. Cuenta de Marta Jiménez (Administración):**

```bash
curl --ssl-reqd --insecure \
  --user marta.jimenez \
  --upload-file /tmp/expediente-administrativo.txt \
  ftp://192.168.50.1/archivos/expediente-administrativo.txt
```

Curl solicitará la contraseña correspondiente de la funcionaria.

**2. Cuenta de Sofía Hernández (Docencia):**

```bash
curl --ssl-reqd --insecure \
  --user sofia.hernandez \
  --upload-file /tmp/planificacion-docente.txt \
  ftp://192.168.50.1/archivos/planificacion-docente.txt
```

**3. Cuenta de Valeria Sánchez (Informática):**

```bash
curl --ssl-reqd --insecure \
  --user valeria.sanchez \
  --upload-file /tmp/informe-soporte.txt \
  ftp://192.168.50.1/archivos/informe-soporte.txt
```

**4. Listar contenido del directorio personal:**

```bash
curl --ssl-reqd --insecure \
  --user marta.jimenez \
  ftp://192.168.50.1/archivos/
```

La opción `--insecure` se utiliza únicamente porque el laboratorio opera con un certificado autofirmado generado internamente.
