# PASO 09.08 — Comprobar que los permisos funcionan

> **Naturaleza:** procedimiento reproducible derivado íntegramente de la guía compartida, con correcciones para el repositorio. **No implica que el paso esté verificado en todas las máquinas.**
>
> **Origen:** `docs/fuentes/GUIA-HISTORICA-INTEGRA.md`; capturas reales de la última bitácora cuando existen.

## Antes de ejecutar

- [ ] Identificar VM, interfaz e IP actual; no asumir la IP de otra persona.
- [ ] Inspeccionar el estado actual del servicio. Si hay datos o volúmenes existentes, respaldarlos antes de cambios.
- [ ] Registrar fecha, integrante responsable, revisor y versión vigente en la sesión de bitácora.

## Procedimiento completo y comandos originales

Iniciá sesión como `ftpdocencia` e intentá acceder a un archivo de `ftpadmin`.

Una ruta que podés intentar consultar es:

```
/../ftpadmin/archivos/administracion.txt
```

El acceso debe fallar o quedar restringido al directorio raíz del usuario autenticado.

También podés comprobar los permisos desde Ubuntu:

```
ls -ld /srv/ftp/*
```

Y:

```
ls -ld /srv/ftp/*/archivos
```

Los archivos departamentales no deben quedar disponibles para modificación por cualquier usuario del servidor.

Evidencia 6: captura de las cinco cuentas, sus directorios y una prueba en la que un usuario intenta acceder a los archivos de otro y recibe una denegación.

# PASO 10. Automatizar respaldos con Cron

Este requisito incluye dos partes obligatorias: generar respaldos automáticamente y demostrar que se puede restaurar la base de datos.

Haremos una copia comprimida de MariaDB todos los días.

## Correcciones y precauciones aplicables

No basta ver permisos con `ls`. Probar explícitamente que otra cuenta no pueda listar, escribir, sobrescribir ni borrar un archivo ajeno; usar cuentas de laboratorio.
