## Comprobación recomendada y salida a documentar

`sudo systemctl is-active vsftpd`, prueba FTPS de subida/listado y acceso de usuario A a ruta de B, comprobando rechazo y registrando código de error.

Registrar el resultado exacto, fecha, sistema y si la prueba pasó o falló. Para un cambio de configuración conservar el archivo anterior y ejecutar la validación sintáctica antes de reiniciar el servicio. La **ruta versionable recomendada** está explicada en [`infra/`](../../../infra/README.md), sin sustituir los comandos originales que aparecen abajo.

## Procedimiento completo y comandos originales

Prueba con dos cuentas de departamentos distintos: `marta.jimenez` (dueña del archivo) y `sofia.hernandez` (intruso). Primero subí `administracion.txt` como Marta (09-07).

**A. Desde Mint, FTPS como `sofia.hernandez`** (anotá el código de respuesta de cada uno):

```
curl --ssl-reqd -k --user sofia.hernandez ftp://192.168.50.1/../marta.jimenez/archivos/administracion.txt
curl --ssl-reqd -k --user sofia.hernandez -Q "DELE ../marta.jimenez/archivos/administracion.txt" ftp://192.168.50.1/
```

Esperado: error 550 (o equivalente). **Atención:** dentro del chroot esa ruta no existe, así que el 550 demuestra el confinamiento, no el permiso. Por eso hace falta también la prueba B.

**B. Desde Ubuntu, permisos reales del sistema de archivos:**

```
sudo -u sofia.hernandez cat /srv/ftp/marta.jimenez/archivos/administracion.txt
sudo -u sofia.hernandez rm /srv/ftp/marta.jimenez/archivos/administracion.txt
sudo -u sofia.hernandez ls /srv/ftp/marta.jimenez/archivos
```

Esperado: `Permission denied` en los tres. Luego `ls -ld /srv/ftp/*` y `ls -ld /srv/ftp/*/archivos` (raíz `root:root 755`, `archivos` propiedad de la cuenta y modo `700`) y comprobá que el archivo de Marta sigue existiendo.

**C. Prueba positiva:** `marta.jimenez` lista, sube y borra **su propio** archivo con éxito.

Evidencia 6: captura de las seis cuentas y sus directorios, y de A, B y C con los códigos y mensajes visibles (sin contraseñas).

## Correcciones y precauciones aplicables

No basta ver permisos con `ls`. Probar explícitamente que otra cuenta no pueda listar, escribir, sobrescribir ni borrar un archivo ajeno; usar cuentas de laboratorio.
