## Propósito del paso y contexto operacional

En la arquitectura de servidores del **Colegio Técnico de Costa Rica**, la base de datos de Moodle almacena información confidencial y crítica: cuentas de usuario, expedientes académicos, calificaciones ponderadas, preguntas de cuestionarios y hashes de contraseñas. 

Este subpaso inicializa el directorio institucional de almacenamiento local de copias de seguridad en `/var/backups/moodle`. La elección de `/var/backups/` se apega al estándar de jerarquía del sistema de archivos de Linux (FHS, *Filesystem Hierarchy Standard*), reservado específicamente para el resguardo del estado del sistema y servicios esenciales.

### Justificación de seguridad y privacidad (`chmod 700 root:root`)
El volcado relacional de MariaDB contiene datos personales protegidos por la **Ley N° 8968 de Protección de la Persona frente al Tratamiento de sus Datos Personales** de Costa Rica. Por ello, es mandatorio asignar permisos restrictivos `0700` (`drwx------`) y propiedad `root:root`:
- Impide que usuarios sin privilegios del sistema o atacantes locales puedan inspeccionar o sustraer volcados SQL.
- Aísla los respaldos de las cuentas virtuales del servicio FTPS (`vsftpd`) y del usuario web (`www-data`).
- Garantiza que solo el superusuario y los procesos desatendidos de Cron tengan permisos de lectura, escritura y ejecución sobre dicho directorio.

## Comprobación recomendada y salida a documentar

Verificar la creación del directorio, propiedad de root y máscara de permisos mediante `stat` y `ls -ld`:
```bash
stat -c "%a %U:%G %n" /var/backups/moodle
```
Salida requerida:
```
700 root:root /var/backups/moodle
```

## Antes de ejecutar

- [ ] Identificar que la sesión de terminal corresponde a Ubuntu Server (`server`, `192.168.50.1`).
- [ ] Verificar espacio disponible en el disco raíz mediante `df -h /` para asegurar capacidad suficiente para almacenar las copias de seguridad.
- [ ] Confirmar privilegios de superusuario (`sudo`).

## Procedimiento completo y comandos originales

1. Creá el directorio de respaldos para Moodle en la ruta estándar del sistema:

   ```bash
   sudo mkdir -p /var/backups/moodle
   ```

2. Protegé el directorio asignando permisos estrictos `0700`:

   ```bash
   sudo chmod 700 /var/backups/moodle
   ```

3. Asegurá que el propietario y grupo correspondan a `root`:

   ```bash
   sudo chown root:root /var/backups/moodle
   ```

4. Verificá los permisos aplicados:

   ```bash
   ls -ld /var/backups/moodle
   ```

   Debe devolver:
   ```
   drwx------ 2 root root 4096 ... /var/backups/moodle
   ```

## Correcciones y precauciones aplicables

- **Expansión de comodines:** Debido a que el directorio tiene permisos `0700 root:root`, los usuarios no privilegiados no pueden listar su contenido directamente. Cualquier comprobación con comodines (`*`) bajo `sudo` debe ejecutarse en una subshell de root (`sudo sh -c '...'`) para evitar el error `No such file or directory` detectado en el incidente INC-012.
- **Espacio en disco:** Supervisar periódicamente el almacenamiento con `du -sh /var/backups/moodle`. La política de retención móvil de 7 días configurada en el script de respaldo previene el agotamiento de espacio.
