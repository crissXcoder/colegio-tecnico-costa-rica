## Propósito del paso y contexto operacional

Este subpaso implementa la lógica de respaldo automatizado para el motor relacional MariaDB 11.4.13 que sustenta la plataforma Moodle. El script `respaldo.sh` automatiza las siguientes funciones críticas:

1. **Ubicación contextual y variables de entorno:** Utiliza `PROJECT_DIR` dinámico para resolver rutas absolutas independientemente del directorio de llamada, cargando las credenciales protegidas desde `.env` sin exponerlas en texto plano en la línea de comandos ni en la tabla de procesos (`ps`).
2. **Volcado ACID sin bloqueo de tablas (`--single-transaction`):** Ejecuta `mariadb-dump` sobre las tablas InnoDB del esquema Moodle dentro de una transacción coherente, evitando bloqueos globales de lectura que interrumpan a estudiantes o profesores mientras navegan por el aula virtual.
3. **Flujo por tubería y compresión continua (`gzip`):** La salida del volcado SQL se canaliza directamente hacia `gzip` en memoria antes de tocar el almacenamiento secundario, reduciendo el tamaño en disco de ~1.8 MB a ~384 KB (ahorro del 80%) y optimizando el tiempo de I/O.
4. **Verificación de integridad en línea:** Valida que el archivo generado no esté vacío (`test -s`) y que la estructura comprimida sea íntegra (`gzip -t`).
5. **Retención móvil estricta (7 días):** Depura automáticamente los volcados que superen los 7 días mediante `find -mtime +7 -delete`, manteniendo un balance óptimo entre histórico de recuperación y consumo de almacenamiento.

### Parámetros técnicos de `mariadb-dump`
| Parámetro | Función técnica en el Colegio Técnico |
|---|---|
| `-u root` | Autenticación con la cuenta administrativa interna de MariaDB. |
| `-e MYSQL_PWD="$DB_ROOT_PASSWORD"` | Inyección segura de la contraseña por variable de entorno de sesión, sin aparecer en el historial ni en `ps`. |
| `--single-transaction` | Garantiza consistencia transaccional ACID de las 494 tablas de Moodle sin bloquear escrituras. |
| `--quick` | Fuerza a recuperar filas una por una del servidor en lugar de almacenar en búfer en RAM, vital para no agotar la memoria de la VM. |
| `--routines` | Incluye en el volcado los procedimientos almacenados y funciones definidas en la base de datos. |
| `--events` | Incluye los eventos programados en el motor relacional. |
| `moodle` | Base de datos relacional de producción del CTCR. |

## Procedimiento completo y comandos originales

1. Ubicate en el directorio del proyecto Moodle:

   ```bash
   cd ~/proyecto-moodle
   ```

2. Creá el script de respaldo:

   ```bash
   nano respaldo.sh
   ```

3. Pegá el contenido institucional del script:

   ```bash
   #!/bin/bash

   set -euo pipefail
   umask 077

   export PATH="/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"

   PROJECT_DIR="$(cd "$(dirname "$0")" && pwd)"
   BACKUP_DIR="/var/backups/moodle"
   FECHA=$(date +%Y-%m-%d_%H-%M-%S)

   cd "$PROJECT_DIR"

   # Cargar las credenciales de la base de datos de forma protegida
   set -a
   source .env
   set +a

   mkdir -p "$BACKUP_DIR"

   # Archivo de respaldo con nomenclatura oficial institucional
   ARCHIVO="$BACKUP_DIR/ctcr_moodle_$FECHA.sql.gz"

   # Crear copia de seguridad comprimida de MariaDB mediante tubería sin TTY
   docker compose exec -T \
       -e MYSQL_PWD="$DB_ROOT_PASSWORD" \
       db mariadb-dump \
       -u root \
       --single-transaction \
       --quick \
       --routines \
       --events \
       moodle \
       | gzip > "$ARCHIVO"

   # Comprobar que el archivo existe y no esté vacío
   test -s "$ARCHIVO"

   # Comprobar la integridad de la compresión gzip
   gzip -t "$ARCHIVO"

   # Aplicar la política de retención institucional (conservar últimos 7 días)
   find "$BACKUP_DIR" \
       -type f \
       -name "ctcr_moodle_*.sql.gz" \
       -mtime +7 \
       -delete

   echo "Respaldo completado correctamente: $FECHA"
   ```

4. Guardá el archivo (`Ctrl + O`, `Enter`, `Ctrl + X`).

## Correcciones y precauciones aplicables

- **Inclusión de `export PATH`:** En entornos de Cron, la variable `PATH` suele ser muy reducida (`/usr/bin:/bin`). Incluir la ruta completa a nivel de script garantiza que herramientas como `docker` y `docker compose` se ubiquen sin fallos.
- **Opción `-T` en Docker Compose:** Al ejecutarse de forma desatendida desde Cron o tuberías, `docker compose exec` debe invocarse con `-T` para deshabilitar la asignación de un pseudo-TTY, evitando el error `the input device is not a TTY`.
