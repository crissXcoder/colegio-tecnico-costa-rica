## Propósito del paso y contexto operacional

Este subpaso asegura que el script de respaldo cuente con los permisos de ejecución necesarios en el sistema de archivos POSIX, garantizando al mismo tiempo que permanezca completamente blindado frente a accesos no autorizados.

### Asignación de permisos (`chmod 700`)
El script carga de manera dinámica el archivo `.env` que contiene secretos de alta sensibilidad, incluyendo la clave maestra del superusuario `DB_ROOT_PASSWORD`. Asignar permisos `0700` (`-rwx------`) asegura que:
- Solo el usuario propietario (y `root` por delegación de superusuario) pueda leer, modificar o ejecutar el script.
- Ningún otro usuario del sistema (incluyendo usuarios de servicios web o de red) pueda leer el código fuente del script ni extraer las credenciales.

### Validación estática con `bash -n`
Antes de planificar cualquier script en el subsistema de tareas automáticas Cron de root, es indispensable validar su corrección gramatical. La opción `-n` (*noexec*) de Bash analiza la sintaxis completa del script (árbol de sintaxis abstracta) sin invocar comandos:
- Detecta comillas sin cerrar, variables mal referenciadas o bloques de tubería rotos.
- Previene que el programador de tareas falle silenciosamente durante la madrugada por un error tipográfico.

## Comprobación recomendada y salida a documentar

1. Comprobar los permisos del archivo con `ls -l`:
   ```bash
   ls -l /home/criss/proyecto-moodle/respaldo.sh
   ```
   Debe devolver `-rwx------ 1 criss criss ...`.

2. Ejecutar la validación sintáctica:
   ```bash
   bash -n /home/criss/proyecto-moodle/respaldo.sh
   ```
   Debe finalizar con código de salida `0` (sin imprimir líneas de error).

## Antes de ejecutar

- [ ] Confirmar que el archivo `respaldo.sh` fue creado en el paso 10.02.
- [ ] Verificar que la sesión de usuario actual tiene permisos para modificar el archivo.

## Procedimiento completo y comandos originales

1. Ubicate en el directorio del proyecto:

   ```bash
   cd ~/proyecto-moodle
   ```

2. Asigná permisos estrictos de ejecución únicamente al propietario:

   ```bash
   chmod 700 respaldo.sh
   ```

3. Comprobá que no existen errores de sintaxis en el intérprete Bash:

   ```bash
   bash -n respaldo.sh
   ```

   Si la consola no imprime ninguna advertencia ni mensaje de error y retorna al prompt, el script es gramaticalmente correcto.

4. Verificá el código de retorno del comando anterior:

   ```bash
   echo $?
   ```

   Debe devolver `0`.

## Correcciones y precauciones aplicables

- **No usar `chmod 777`:** Nunca asignar permisos de lectura o ejecución a grupos u otros (`world-readable`) a scripts que cargan variables de bases de datos.
- **Validación previa a Cron:** No programar scripts en el crontab sin haber comprobado previamente que pasan `bash -n`.
