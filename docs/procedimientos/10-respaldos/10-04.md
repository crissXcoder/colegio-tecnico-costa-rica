## Propósito del paso y contexto operacional

Respaldo y restauración: dump SQL, retención, datos de Moodle y ensayo separado sin destruir producción de laboratorio.

Este archivo corresponde **exclusivamente al paso 10-04**, con comandos históricos literales y mejoras razonadas. En una **VM ya configurada** se inspeccionan primero los servicios y datos; no se vuelven a crear credenciales ni volúmenes. Los resultados observados en las capturas pertenecen a la sesión que los originó, no al conjunto de cinco integrantes.

## Comprobación recomendada y salida a documentar

Comprobar `sudo crontab -l`, archivo `moodle_*.sql.gz` no vacío, `gzip -t`, restaurar `moodle_restore_test`, contar tablas y comprobar archivos moodledata con procedimiento aparte.

Registrar el resultado exacto, fecha, sistema y si la prueba pasó o falló. Para un cambio de configuración conservar el archivo anterior y ejecutar la validación sintáctica antes de reiniciar el servicio. La **ruta versionable recomendada** está explicada en [`infra/`](../../../infra/README.md), sin sustituir los comandos originales que aparecen abajo.

## Antes de ejecutar

- [ ] Identificar VM, interfaz e IP actual; no asumir la IP de otra persona.
- [ ] Inspeccionar el estado actual del servicio. Si hay datos o volúmenes existentes, respaldarlos antes de cambios.
- [ ] Registrar fecha, integrante responsable, revisor y versión vigente en la sesión de bitácora.

## Procedimiento completo y comandos originales

```
sudo ./respaldo.sh
```

Resultado esperado:

```
Respaldo completado: 2026-10-21_...
```

La fecha y hora corresponderán al momento de la ejecución.

Verificá los archivos:

```
sudo ls -lh /var/backups/moodle
```

Y la integridad:

```bash
sudo sh -c 'gzip -t /var/backups/moodle/*.sql.gz && echo "Integridad OK"'
```

> **Nota sobre permisos:** Dado que `/var/backups/moodle` tiene permisos `0700 root:root`, ejecutar `sudo gzip -t /var/backups/moodle/*.sql.gz` directamente en una shell no privilegiada fallará la expansión del comodín `*` antes de que `sudo` tome efecto. Se debe ejecutar dentro de una subshell de root (`sudo sh -c '...'`) o especificando el nombre completo del archivo.

Si el último comando no muestra errores, el archivo comprimido es válido. Esto todavía no garantiza que la base de datos se pueda restaurar; lo probaremos a continuación.

## Correcciones y precauciones aplicables

Antes de copiar comandos comprueben si es un servidor nuevo o una VM ya configurada; adaptar rutas, IP, interfaces, nombres y versiones, y guardar evidencia del resultado.
