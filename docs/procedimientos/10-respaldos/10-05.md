## Propósito del paso y contexto operacional

En un entorno educativo en producción como el **Colegio Técnico de Costa Rica**, los respaldos no pueden depender de la intervención humana manual. La automatización mediante el programador de tareas Cron de Linux garantiza la continuidad operativa y la conservación diaria del estado de la plataforma Moodle.

### Elección de la hora: 02:00 a. m. CST
- **Mínima concurrencia:** A las 2:00 a. m. no hay estudiantes realizando cuestionarios evaluables ni profesores subiendo material didáctico, lo que reduce al mínimo el impacto sobre los recursos de CPU/disco de la VM.
- **Ventana de mantenimiento:** Permite completar la compresión y retención antes del inicio de la jornada laboral institucional a las 07:00 a. m.

### Sincronización temporal con `timedatectl`
Para que la tarea programada a las 02:00 a. m. coincida con la hora local real y no con el tiempo universal coordinado (UTC), es indispensable verificar y fijar la zona horaria del servidor en `America/Costa_Rica` (CST, UTC-6).

### Desglose de la directiva de Crontab
```
0 2 * * * /home/criss/proyecto-moodle/respaldo.sh >> /var/log/moodle-backup.log 2>&1
```
| Campo | Valor | Significado técnico |
|---|---|---|
| Minuto | `0` | En el minuto cero de la hora. |
| Hora | `2` | A las 2:00 de la madrugada. |
| Día del mes | `*` | Todos los días del mes. |
| Mes | `*` | Todos los meses del año. |
| Día de semana | `*` | Todos los días de la semana (domingo a sábado). |
| Comando | `/home/criss/.../respaldo.sh` | Ruta absoluta al script ejecutable. |
| Redirección stdout | `>> /var/log/moodle-backup.log` | Concatena la salida estándar en la bitácora institucional. |
| Redirección stderr | `2>&1` | Canaliza la salida de error estándar a la misma bitácora para depuración forense. |

## Comprobación recomendada y salida a documentar

1. Comprobar la zona horaria institucional:
   ```bash
   timedatectl
   ```
   Debe mostrar `Time zone: America/Costa_Rica (CST, -0600)` y `NTP service: active`.

2. Comprobar el servicio Cron:
   ```bash
   sudo systemctl is-active cron
   ```
   Debe devolver `active`.

3. Consultar las tareas programadas de root:
   ```bash
   sudo crontab -l
   ```
   Debe mostrar la tarea programada al final del archivo.

## Antes de ejecutar

- [ ] Verificar que `respaldo.sh` funciona correctamente tras la prueba manual del paso 10.04.
- [ ] Confirmar la ruta absoluta del proyecto (`pwd`) para no copiar rutas de otros usuarios.

## Procedimiento completo y comandos originales

1. Comprobá la zona horaria del servidor:

   ```bash
   timedatectl
   ```

2. Si no está configurada la hora oficial de Costa Rica, aplicala con:

   ```bash
   sudo timedatectl set-timezone America/Costa_Rica
   ```

3. Abrí el editor de tareas de superusuario:

   ```bash
   sudo crontab -e
   ```

   *(Si es la primera vez que se ejecuta, seleccioná la opción recomendada `nano`).*

4. Al final del archivo, agregá la siguiente línea (ajustando la ruta al usuario de tu servidor, por ejemplo `/home/criss`):

   ```
   0 2 * * * /home/criss/proyecto-moodle/respaldo.sh >> /var/log/moodle-backup.log 2>&1
   ```

5. Guardá los cambios (`Ctrl + O`, `Enter`, `Ctrl + X`).

6. Asegurá que el servicio Cron esté habilitado y activo en el arranque del sistema:

   ```bash
   sudo systemctl enable --now cron
   ```

7. Verificá el estado activo del servicio:

   ```bash
   sudo systemctl is-active cron
   ```

8. Comprobá que la tarea quedó registrada en el crontab de root:

   ```bash
   sudo crontab -l
   ```

## Correcciones y precauciones aplicables

- **Crontab de root vs crontab de usuario:** Se debe usar `sudo crontab -e` (crontab de `root`) porque el script requiere permisos de Docker y acceso de escritura sobre `/var/backups/moodle/` (`0700 root:root`).
- **Máquina virtual encendida:** La tarea de Cron solo se ejecutará a las 02:00 a. m. si la máquina virtual de Ubuntu Server permanece encendida. Para demostraciones académicas, se complementa con la ejecución manual verificada en 10.04.
