## Propósito del paso y contexto operacional

Respaldo y restauración: dump SQL, retención, datos de Moodle y ensayo separado sin destruir producción de laboratorio.

Este archivo corresponde **exclusivamente al paso 10-06**, con comandos históricos literales y mejoras razonadas. En una **VM ya configurada** se inspeccionan primero los servicios y datos; no se vuelven a crear credenciales ni volúmenes. Los resultados observados en las capturas pertenecen a la sesión que los originó, no al conjunto de cinco integrantes.

## Comprobación recomendada y salida a documentar

Comprobar `sudo crontab -l`, archivo `moodle_*.sql.gz` no vacío, `gzip -t`, restaurar `moodle_restore_test`, contar tablas y comprobar archivos moodledata con procedimiento aparte.

Registrar el resultado exacto, fecha, sistema y si la prueba pasó o falló. Para un cambio de configuración conservar el archivo anterior y ejecutar la validación sintáctica antes de reiniciar el servicio. La **ruta versionable recomendada** está explicada en [`infra/`](../../../infra/README.md), sin sustituir los comandos originales que aparecen abajo.

- [ ] Inspeccionar el estado actual del servicio. Si hay datos o volúmenes existentes, respaldarlos antes de cambios.

## Procedimiento completo y comandos originales

No vamos a borrar ni sobrescribir la base de datos real.

Crearemos una segunda base de datos, llamada `moodle_restore_test`, e importaremos allí la copia.

Primero entrá:

```
cd ~/proyecto-moodle
```

Cargá las variables:

```
set -a
source .env
set +a
```

Creá la base de prueba:

```
sudo docker compose exec -T \
  -e MYSQL_PWD="$DB_ROOT_PASSWORD" \
  db mariadb -u root \
  -e "CREATE DATABASE IF NOT EXISTS moodle_restore_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
```

Ahora recuperá la ruta del respaldo más reciente:

```
BACKUP=$(sudo find /var/backups/moodle \
  -name 'moodle_*.sql.gz' \
  -type f \
  -printf '%T@ %p\n' \
  | sort -nr \
  | head -1 \
  | cut -d' ' -f2-)
```

Comprobá:

```
echo "$BACKUP"
```

Debe mostrar la ruta de un archivo `.sql.gz`.

Restaurá:

```
sudo gzip -dc "$BACKUP" | \
sudo docker compose exec -T \
  -e MYSQL_PWD="$DB_ROOT_PASSWORD" \
  db mariadb -u root moodle_restore_test
```

Si el comando termina correctamente, verificá que se hayan recuperado las tablas:

```
sudo docker compose exec -T \
  -e MYSQL_PWD="$DB_ROOT_PASSWORD" \
  db mariadb -u root \
  -N -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema = 'moodle_restore_test';"
```

El resultado debe ser un número mayor que cero.

Eso demuestra que el archivo SQL se importó en una base independiente. Para una validación más completa, compará el número de tablas de la base original y el de la restaurada.

Después de guardar la evidencia, podés eliminar únicamente la base de prueba:

```
sudo docker compose exec -T \
  -e MYSQL_PWD="$DB_ROOT_PASSWORD" \
  db mariadb -u root \
  -e "DROP DATABASE moodle_restore_test;"
```

Nunca utilicés `DROP DATABASE moodle` para este procedimiento.

## Correcciones y precauciones aplicables

Una restauración SQL en base separada es el mínimo de prueba. No usar la base de producción como destino ni publicar sus datos. Evitar mostrar credenciales en las capturas.
