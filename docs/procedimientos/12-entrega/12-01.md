## Propósito del paso y contexto operacional

Documentación reproducible, informe técnico, demostración en vivo y enlace entre rúbrica y evidencias.

Este archivo corresponde **exclusivamente al paso 12-01**, con comandos históricos literales y mejoras razonadas. En una **VM ya configurada** se inspeccionan primero los servicios y datos; no se vuelven a crear credenciales ni volúmenes. Los resultados observados en las capturas pertenecen a la sesión que los originó, no al conjunto de cinco integrantes.

## Comprobación recomendada y salida a documentar

Auditar enlaces, cifras de rúbrica, evidencias asociadas y ejecución cruzada antes del ensayo del 6/11 y entrega 7/11/2026.

Registrar el resultado exacto, fecha, sistema y si la prueba pasó o falló. Para un cambio de configuración conservar el archivo anterior y ejecutar la validación sintáctica antes de reiniciar el servicio. La **ruta versionable recomendada** está explicada en [`infra/`](../../../infra/README.md), sin sustituir los comandos originales que aparecen abajo.

Este bloque construye el informe final **a partir del repositorio** y respeta la plantilla académica aportada (sin inventar resultados):

1. Introducción al incidente escolar y necesidad de permisos; contexto Colegio Técnico.
2. Justificar software libre: Moodle vs Chamilo y otras soluciones LMS, MariaDB y alternativas, Ubuntu, Nginx, BIND9 y vsftpd.
3. Diagrama real: NAT Ubuntu, red interna Mint, BIND9, Nginx TLS, Compose Moodle/MariaDB, volúmenes y Cron/FTPS.
4. Versiones exactas observadas, incluyendo `docker image inspect` y digests registrados.
5. Por fase: objetivo, decisiones, comandos/configuración completa, evidencia original, error/resolución, resultado verificado.
6. Tres cursos: al menos 2 recursos genuinos y 1 actividad evaluable cada uno; capturas de la actividad completada cuando proceda.
7. Seguridad: matriz 3x3 de accesos y seis denegaciones, además de URL directa a recurso ajeno, privilegios del profesor restringido y FTPS aislado.
8. Restauración de respaldo SQL, recuperación y consistencia de archivos, validación de Cron.
9. Decisiones/tradeoffs, conclusiones y anexos enlazados a los archivos reales de infraestructura.

**Comandos útiles de evidencia en Ubuntu** (no exponen contraseñas):

```bash
cat /etc/os-release
docker --version
docker compose version
sudo docker compose ls
sudo docker volume ls
sudo systemctl is-active named nginx vsftpd cron
sudo ss -lntup
sudo ufw status verbose
sudo named-checkconf
sudo named-checkzone ctcr /etc/bind/db.ctcr
sudo nginx -t
```

**Desde Linux Mint**:

```bash
ping -c 4 192.168.50.1
getent hosts aulavirtual.ctcr
curl -kI https://aulavirtual.ctcr
```

Guardar por prueba resultado esperado, resultado obtenido y evidencia. Verificar que las URL y los accesos negativos no dependen de sesión `admin`. Antes de exponer cualquier captura del informe, revisar información personal y credenciales.

La entrega no se puede considerar completada hasta que un integrante diferente al autor reproduzca las instrucciones o contraste físicamente la infraestructura en una reunión.
